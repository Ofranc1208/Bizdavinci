# BIZ DA VINCI — MASTER PROJECT CONTEXT

## 1. Product Identity

**Name:** Biz Da Vinci

**Business:** Website modernization, AI-assisted website analysis, digital design, and marketing services.

**Primary audience:** Small and established businesses with outdated websites, especially local service providers and professional businesses.

**Positioning:** A premium technology-enabled agency offering useful website insights, modern redesign previews, free DIY resources, and transparent professional services.

**Philosophy:** Give customers genuine value before selling anything. Make the process simple, accessible, flexible, and trustworthy.

A customer should never feel pressured to hire Biz Da Vinci.

A previous investigation reported that the Git repository might be rooted in the user's home directory and that a root `.env.local` contains an OpenAI API key.

Verify those conditions before changing repository or environment configuration.

Never print, expose, commit, or send secrets to the frontend. Check for accidental tracking or historical exposure and report any required remediation.

## 4. The Website Analysis Experience

The system begins with a website URL.

The backend should safely inspect permitted public websites, extract useful business information, and capture a real screenshot.

Information to collect when available:

- Final resolved website URL.
- Business name.
- Industry or profession.
- Logo.
- Main services.
- Website navigation.
- Homepage title and description.
- Relevant page headings.
- Public contact information.
- Basic page inventory.
- Primary calls to action.
- Limited branding information.

The system must distinguish verified information from assumptions.

Do not invent phone numbers, customer testimonials, licensing, reviews, certifications, locations, or business achievements.

If industry classification is uncertain, support an unknown result or allow customers to correct the category.

### Website screenshot

The Before side of the comparison must display an actual captured screenshot.

Do not rely on third-party iframe embedding.

Use safe browser automation with appropriate resource limits, timeouts, URL restrictions, and honest failure handling.

### Website redesign

The After side should use curated industry-specific templates, not a completely new AI-generated design every time.

Potential industries include:

- Plumbing and HVAC.
- Medical spas.
- Dental practices.
- Healthcare.
- Home services.
- Professional services.

Match businesses to available templates and personalize them using verified information.

Keep template selection, business content extraction, and frontend rendering separate.

## 5. Website Auditing

The audit should eventually explain what can be improved in straightforward language.

Possible categories:

- Mobile experience.
- Website performance.
- Navigation clarity.
- Basic technical SEO.
- Content structure.
- Accessibility.
- Contact and conversion opportunities.
- Trust and business information presentation.

Only show measurements that have actually been performed.

Use reliable sources and tools for measurable findings.

Do not present subjective design opinions as objective measurements.

Support incomplete analyses and clearly identify unavailable information.

## 6. The Free AI Website Blueprint

This is one of our most important product differentiators.

**The AI website blueprint must be genuinely free.**

A visitor should receive a useful, detailed prompt that helps them build or improve their website independently.

It should be usable with Claude Code, ChatGPT, Codex, or other capable coding tools.

The blueprint should include:

- Website improvement summary.
- Existing business information, marked as verified or uncertain.
- Proposed website structure.
- Recommended pages.
- Industry-relevant layout guidance.
- Design direction.
- Suggested homepage content structure.
- SEO recommendations.
- Mobile and accessibility considerations.
- Recommended website features.
- Technical implementation guidance.
- A detailed, copyable AI development prompt.

Provide an easy way to copy and download the blueprint.

Do not require an email address, account, consultation, or purchase to access it.

Be transparent about any unavailable information or analysis limitations.

Customers own their downloaded brief and can take it to another provider or build the website themselves.

This is a permanent first-class option, not a limited trial.

- Improve mobile layout.

At that point, the visitor can:

**A.** Download the free AI website-building blueprint.

## 10. Architecture Principles

Build a self-contained, independently maintainable Biz Da Vinci product.

Prefer clear module boundaries for:

- Website capture.
- Safe URL processing.
- HTML and business-content extraction.
- Industry classification.
- Template selection.
- Redesign preview preparation.
- Website auditing.
- AI blueprint generation.
- Pricing rules.
- Proposal preparation.

Independent modules do not necessarily require independently deployed microservices.

Reuse the existing framework wherever practical.

Add infrastructure only when needed.

Security requirements include preventing server-side request forgery, private-network access, browser sandbox escapes, unsafe redirects, credential exposure, abusive crawling, and resource exhaustion.

Browser capture must be isolated from sensitive local resources.

Respect public website access restrictions and do not attempt to bypass access controls.

Do not expose API keys to browsers.

Minimize retention of captured data and business information.

Do not introduce a production database or cloud service without evaluating whether it is necessary.

## 11. Development Process

The intended development approach is:

1. Inspect the existing repository.
2. Inventory real versus demonstration capabilities.
3. Review the approved frontend.
4. Define a minimal architecture.
5. Implement in independently testable stages.
6. Add automated tests.
7. Test with actual public websites.
8. Validate industry identification.
9. Verify the redesign preview.
10. Implement and test the free blueprint.
11. Connect quotation and service configuration.
12. Review the entire customer journey.

Work locally first.

Do not deploy, push code, purchase services, or change production infrastructure without authorization.

Biz Da Vinci succeeds when:

- A real public URL can be submitted safely.

- The appropriate available template appears in the After panel.
- The existing comparison slider remains functional.
