## Executive summary

The local demo is in **good shape security-wise**. The server guard holds against every traversal variant tried, there is no reachable XSS from URL, form or storage input, there are no secrets or real contact data, and there are no external resources. The main risks are **maintainability and drift**. The code now has **36 professions and 48 routes**, but every doc and QA record still says 18 and 30. The CSS is a stack of revision layers that override each other. `app.js` is a single-file app. Escaping is inconsistent, which is harmless with static data but becomes an XSS hole as soon as content becomes dynamic.

### Top 5 to fix first
1. **F1 (High): docs and QA drift.** The code has 36 professions, 48 routes, 11 categories and 9 tests. The docs say 18, 30, 8 and 8 (`README.md:3`, `docs/STATUS.md:7,19`, `docs/PAGE_MAP.md:11,24-45,47`, `frontend/README.md:22,41`). QA evidence (`qa/dedicated-pages/http-results.json`) covers none of the 18 newer profiles. `professions.js` lines 22–974 were added after the docs.
2. **S6 (Medium): inconsistent HTML escaping.** Data is interpolated raw in `components.js:13,17,18`, `app.js:21,25,27,29,30`, while `pages.js` escapes the same fields. Adopt one auto-escaping template helper before any CMS, AI or user-sourced content arrives.
3. **F6 (Medium): unvalidated registry and null dereferences.** These can blank the whole app: `pages.js:11` (hard-coded featured slugs), `pages.js:13` (`related` lookups, `faq[0]/[1]`), `model.js:28` (`needs[0][1]`), `app.js:104`. Add a schema test and guards.
4. **F8 (Medium): tests skip the risky parts.** There are no tests for the `serve.mjs` path guard (the only security boundary) or for `app.js` routing, state and events. `npm run check` (`package.json:11`) skips `tests/` and `qa.html`.
5. **F2 + R1 (Medium): CSS override chain.** `polish.css` has five dated revision layers (lines 1, 83, 154, 195, 224) on top of `styles.css`. `.hero h1` font-size is declared 15 times, `:root` 3 times, and the element carries `comparison comparison-v2 comparison-v3` classes at once (`components.js:22`). Fold the layers into one stylesheet per component.

**Biggest monoliths:**
- `app.js`: templates, copy, router, store, every event handler, widget controllers and download, all in one file.
- The CSS trio, with `polish.css` as a patch layer.
- `professions.js`: a 53 KB content database inside JS, in two different formats.

**Main redundancy themes:**
- CSS re-declaration: 191 selectors re-declared across files and 10 exact duplicate rules.
- Duplicated FAQ content.
- Duplicated enums and magic strings across `app.js`, `model.js` and `pages.js`.
- Duplicated navigation and route labels.
- Dead legacy comparison CSS and unused JS imports and fields.
- The fictional brands (Forma, Aurelia, Evergreen, Oakwell, Northline) are defined in both `data.js` and `professions.js`.

## What's in good shape
- **Static server guard is sound.** Every traversal and encoding variant tried was rejected. It binds only to `127.0.0.1`, allows GET/HEAD only, returns 404 without leaking stack traces, sends `nosniff` and uses an explicit file allowlist (`serve.mjs:12-21`).
- **Untrusted input is handled correctly.** The URL is normalized (query, hash and credentials stripped; `javascript:` and `ftp:` rejected) and escaped on display. Contact fields are escaped. Stored state is fully whitelisted by `sanitizeState` (no prototype pollution, duplicate add-ons removed). The profession query is resolved against the registry. Hash anchors use `getElementById`.
- **Privacy matches the product promises.** Contact details stay in memory only, nothing is sent, and the download is a local Blob with a fixed filename. No secrets, real Tampa lead data or contact records exist in the fixtures. There are no third-party requests (fonts and images are local, with license files and documented provenance).
- **Clean module graph.** There are no circular imports, the code has zero dependencies, and the domain logic (`model.js`) is pure and testable in Node.
- **Accessibility basics are present.** Skip link, `main` focus on route change, `aria-live` announcer, `aria-pressed`/`aria-current`, a labelled range with `aria-valuetext`, native `<details>`, `prefers-reduced-motion` and alt text on all content images (0 missing). There are no duplicate ids on the scanned pages, and no horizontal overflow on any of the 48 routes at 360 px and 1440 px.
- **Docs discipline is strong.** Clear ownership in `AGENTS.md`, explicit demo boundaries and honest "not implemented" sections. The problem is only that they are stale (F1).
